# ROS 2 全工作空间本地验证记录

更新日期：2026-11-16。完整迁移仍在集成中；以下仅记录已经实际执行并通过的检查，不代表全部旧功能已经迁移，也不代表实体小车通过验收。

## 当前构建与基础测试

在官方 `ros:humble-ros-base-jammy` 的独立 Ubuntu 22.04 x86_64 根文件系统中，复制出全新的原生 Linux 源码目录后，直接运行交付脚本：

```bash
bash scripts/build.sh
bash scripts/test.sh
bash scripts/install_dependencies.sh --check-only
```

本次构建快照包含 637 个文件，518,623,055 字节，不包括 build/install/log 和 Python 缓存。22 个包全部构建完成，用时 33.1 秒。两个 PCL/OpenCV 包存在第三方 CMake 警告，但构建成功。该时间来自当前本地验证机器，不作为 Jetson 的构建耗时估算。

`scripts/test.sh` 完整执行成功：17 组单元测试合计 **307 项通过**，随后六个基础集成程序全部正常退出：

- `hardware_transport_smoke.py`：原始真实 SDK、pyserial 与 Linux PTY，7 组协议和故障检查。
- `hardware_accessory_smoke.py`：6 组机械臂、查询、版本、静态 RGB、灯效与蜂鸣器实际帧检查。
- `ros_integration.py`：ROS 模拟底盘与运动控制任务的通信和运动状态检查。
- `ros_driver_checks.py`：ROS 底盘节点接口、服务和状态检查。
- `ros_hardware_checks.py`：ROS 节点经真实 SDK/pyserial 接入虚拟固件，验证速度、里程计、传感器、超时、故障及退出停车。
- `ros_accessory_checks.py`：ROS 参数启用/禁用、实测角度服务、实际机械臂指令及 RGB 协议往返，4 组检查。

相应构建、总测试与依赖检查记录的随包副本见 `validation/mainline`；文件名保留运行编号，扩展名为 `.txt`。开发时的源码快照清单保存在控制目录，发布内容则以根目录 `FILE_MANIFEST.json` 单独记录 SHA256。发布副本省略未使用的旧 ORB 词典，并更新了文档和测试入口，不将开发快照清单冒充发布文件清单。

## 导航、机械臂与感知

以下不是只检查接口或使用假的推理输出：

- Nav2 实际服务器读取合成地图、TF、雷达和模拟底盘，完成目标、结果、取消与停止。默认模式、AMCL、命名空间、AMCL 加命名空间四种组合均通过。取消状态为 5，速度在一秒内归零。地图服务实际生成非空 YAML/PGM 文件。
- 实际 slam_toolbox 从合成方形房间激光与里程计 TF 生成 80×80 占据栅格，观测到 1,724 个空闲格和 28 个占据格，并实际广播 `map -> odom`。夹具不发布地图或这条 TF。该初始建图检查不验证运动回环或实车精度，日志为 `slam_toolbox_checks_50.log`。
- MoveIt 2 使用真实 OMPL 规划及控制器动作，在 ros2_control 模拟硬件上完成轨迹执行、关节反馈、夹爪和取消。实体机械臂的 MoveIt 控制器尚未验收。
- 视觉原生图像/IR/点云节点、PCL 点云建图与清图、SSD 与 OpenPose 的实际推理及 DDS 链路均通过相应离线检查。
- YOLO 使用原 ONNX 模型与原验证图片，经实际 ONNX Runtime CPU 推理输出检测结果。默认原阈值 0.88 的六张图片产生六个实际检测；黑图无检测。ROS 图像到识别消息链路已检查。
- MediaPipe 0.10.9 实际旧版解决方案完成空白图与正样本推理，手与人体分别输出实际 21/33 个关键点，Objectron 实际初始化，PointArray 到 PointCloud2 的坐标/颜色/空数据处理通过 DDS 检查。
- Haar 与 dlib 19.24.6 使用实际原始模型，完成正样本检测、68 点预测、眼/唇坐标、空白图状态清空以及实际 DDS 图像往返，4 组检查通过。官方小脸照片测试使用真实照片的二倍缩放，不提供伪造检测框。

MediaPipe、dlib、ONNX SDK 均安装在验证专用的私有目录，没有覆盖宿主机或 ROS 系统 Python。以上结果验证 x86_64，不证明相同二进制 wheel 可用于 Jetson ARM64。

## 语音和便携验证入口

语音核心、巡线、识色、深度跟随、搬运/取物状态机及五个原始导航点，均有实际 ROS 消息或动作服务离线检查。业务状态机测试使用明确标注的模拟 Nav2 动作服务器；Nav2 本体另由前述实际导航闭环验证，二者不能混称。

已经移入 `tests/offline` 的检查通过 `tests/run_offline.py` 选择执行。完整 `--suite core` 已在原生 Linux 构建安装结果上顺序执行 20 个检查程序并全部返回 0，日志为 `portable_core_45.log`，包含 bringup、模型/接口、语音、MoveIt、四种 Nav2 组合、地图保存及原生感知。

## 已修复的问题与保留边界

总回归发现旧串口测试夹具只允许底盘指令，拒绝新版本节点的角度/版本只读查询。已将该 ROS 测试改为支持附件查询的明确虚拟固件，并仅允许两种精确只读查询；启动时仍禁止舵机、扭矩、Flash 写入。基础底盘协议测试继续使用原严格夹具。

集成测试使用隔离网络命名空间和本地 DDS。便携检查验证已安装的包，避免把所有 Windows 挂载源目录加入 Python 路径导致导入延迟或覆盖安装包。

源码覆盖报告检查了 282 个非缓存原始入口，当前所有原始条目均有记录，引用路径均存在。这里的“有记录”包含明确缺失、待审查、上游替代等状态，不等同于 282 个功能全部完成。

用户已选择工作量较少的 ROS 2 主线方案。旧 SLAM 选项、复杂组合传感器启动、旧 IMU 标定、Gazebo、Warehouse、可选 MoveIt 演示及外部 ORB SDK 明确排除，详见 `迁移范围与未移植项.md`。发布源码省略了未使用的 ORB 词典，构建时该外部追踪器默认关闭。Dockerfile 已调整为完整依赖入口，但未执行 Docker daemon 镜像构建。没有进行实体 Jetson、固件、电机、传感器、实际行驶精度或 APK 联调验收。

原底盘阶段的 2026-11-10 记录保存在 `validation/phase1_验证结果_20261110.md`，其中两包和 37 项测试等数字仅代表当时阶段。
