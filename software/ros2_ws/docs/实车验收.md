# 实车验收记录模板

本次用户无法连接 Jetson，以下均为后续待测项。不要把模拟误差作为实车误差。

## 连接资料

提供 Jetson 具体型号、Ubuntu/JetPack/L4T 版本、ROS 版本、控制板固件/原厂镜像信息、底盘串口的 by-id 路径，以及 `scripts/collect_jetson_info.sh` 输出。无需在聊天中发送密码。

确认控制板仍配置为 X3plus，SDK 3.3.9 与固件匹配。驱动不会更改车型 flash 或 PID。固定设备名 `/dev/rosmaster` 应依据真实 VID/PID/唯一序列号创建，不能套用示例 ID。

## 架空轮子验收

1. 关闭原 ROS 1 驱动、原厂 APP 后台等同串口占用者，确认只启动一个新驱动。
2. 真实模式启动后检查 `/base/status` 为反馈新鲜，`/odom_raw`、IMU 和电压持续更新；先不发送非零速度。
3. 在可立即切断电源的条件下，以低速分别检查前进、后退、横移和旋转方向；指令与反馈轴向必须对应。
4. 停止发送速度，测量指令超时停车；通过停止上报或断开数据验证反馈故障处理。断串口后的实际制动行为需单独观察，ROS 零速并不能保证已送达失联控制板。
5. 检查锁定式停止、显式复位、复位后无新指令不运动，以及退出节点停车。
6. 确认原厂 SBUS 接收机、固件优先级与独立硬件接管是否实际存在并生效。

## 封闭场地短距离验收

完成架空检查后再落地。记录 1 m 前进、1 m 后退、90° 左转、90° 右转和横移的实际值、里程计值、误差、速度与地面条件，每项重复多次；CSV 和 ROS bag 作为证据。逐步调整 linear_scale_x/y、限速、协方差与运动测试增益。

检查静止漂移、时间戳持续更新、IMU 单位/轴向、TF 方向与唯一发布者。定位融合接入后关闭底盘同一条 TF 的发布。

## 不在本阶段验收的项目

150 m 道路部署与回收、GNSS 融合定位精度、LoRa 可靠性与失联分级策略、道路感知和多控制源优先级需要各自实现与验证后再开展。本地无车通过只说明软件链路与受测保护分支正常。
