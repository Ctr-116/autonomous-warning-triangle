# X3plus ROS 2 Humble 迁移范围与未移植项说明

## 1. 迁移策略与范围界定

本工作空间面向 Ubuntu 22.04、ROS 2 Humble 及 ROSMASTER X3plus 机器人硬件平台。在整体架构迁移中，项目明确采用了工作量可控且符合 ROS 2 生态标准的“原生主线替代”策略，即全面拥抱 ROS 2 官方推荐的上游主线技术栈：
- 2D 激光建图由 ROS 2 官方主流的 `slam_toolbox` 承接；
- 移动机器人自主导航与路径规划全面基于 `Nav2` (Navigation2) 架构重构；
- 机械臂运动规划与执行调度迁移至 `MoveIt 2` 与 `ros2_control` 体系。

必须明确说明：采用 `Nav2`、`slam_toolbox` 和 `MoveIt 2` 等原生替代方案，并不等同于在代码级完整移植了原 ROS 1 的老算法（例如 Gmapping、Hector、Karto 等）。原 ROS 1 环境中大量过时的建图算法、冗余的启动组合、实验性质的演示节点及历史遗留脚本均已被主动剔除或精简，不再进行逐行直译。

## 2. 构建与验证规模的真实含义

在当前源码树中，原始 20 个功能包配合新增的底盘驱动包 `x3plus_base` 与控制中间件包 `motion_control_pkg`，共计 22 个 ROS 2 包，已全部在独立的 Linux 环境下完成干净构建，并通过了 307 项单元测试及系列集成测试。

静态源码审计记录了全部 282 个非缓存原始文件条目，包含实现映射、上游替代、未移植和待审查状态。它不表示 282 个历史入口全部原样实现。22 个包编译成功与 307 项测试通过，也不代表所有历史可选功能、全部硬件工况及每种启动组合均已验证。

## 3. 硬件交互与驱动边界

在硬件接口与外设支持方面，当前实现的边界如下：
- **底层通信协议**：真实底盘通信协议 SDK、基于 pyserial 的底层串口交互与虚拟 PTY 机制已完成闭环，支持底盘速度控制、超时保护、里程计上报、状态校验以及机械臂实测角度与固件版本的精确只读查询，并支持静态 RGB 与灯效控制协议帧。
- **机械臂控制**：SDK 层已实现机械臂目标帧与实测角度查询，并通过真实 SDK/PTY 验证。MoveIt 2 当前使用 `ros2_control` 模拟硬件进行轨迹执行，尚未对接并验收实体机械臂的轨迹控制器。SDK 协议测试与实体运动验收是两个不同的范围。
- **传感器驱动**：深度相机（如 Astra/Astra Pro）、单线/多线激光雷达（如 YDLidar/SLLidar）以及手柄等硬件的底层驱动均设计为依赖外部独立的 ROS 2 上游标准驱动包或外部硬件节点，不作为私有硬编码驱动打包在核心算法包内部。

## 4. 教学示例与开发残留区分

在源码与资源整理过程中，严格区分了功能节点与纯教学演示及历史残留：
- **OpenCV 教学示例**：原 `yahboomcar_astra` 中包含的 21 个纯 OpenCV 基础教学与图像处理实验脚本（涵盖 1_1 到 4_3 的系列教程），已被统一归档至功能包的示例目录中独立保存。这些文件属于教学参考代码，不作为 ROS 2 运行时节点参与构建、launch 调度或消息通信。
- **备份与冗余文件**：原工程中存在的 `autopilot_main copy.py`、`voice_ctrl_armBK.py` 等备份副本与开发过程临时残留，已被识别并排除出生产源码树，其功能分别由主干重构节点承接。

## 5. 未移植与排除功能清单（按功能领域归类）

经过四组覆盖率审计与工程核对，以下未迁移或主动排除的功能项不属于误判漏报，均在此明确归档与说明：

### 传统 SLAM 与外部视觉 SLAM SDK
- **传统 2D 激光 SLAM**：排除原系统对 Hector SLAM (`hector.launch`)、Karto SLAM (`karto.launch`) 的封装支持；原 Gmapping 算法亦未移植其原始算法核，统一改由 ROS 2 `slam_toolbox` 替代。
- **多传感器与 3D SLAM**：排除 RTAB-Map 的建图与导航封装 (`rtabmap.launch`, `rtabmap_nav.launch`, `yahboomcar_rtabmap.launch`, `yahboomcar_rtabmap_nav.launch`) 及其对应的独立 RViz 显示启动入口 (`view_rtabmap.launch`, `view_rtabmap_nav.launch`)。
- **Cartographer**：排除 ROS 1 下定制的 Cartographer 启动文件 (`cartographer.launch`, `yahboomcar_cartographer.launch`, `view_cartographer.launch`)，推荐按需采用上游标准 `cartographer_ros`。
- **外部 ORB-SLAM2 依赖**：`yahboomcar_slam` 中的视觉点云映射核心已移植为 ROS 2 原生组件，但底层 ORB-SLAM2 追踪器本体需要外部未预置的第三方 SDK 支持，编译选项默认置为关闭状态。

### 自主探索建图
- 排除原工程基于 RRT 算法的自主建图与多点协同探索模块 (`rrt_exploration.launch`, `simple.launch`, `view_rrt_map.launch`)。
- 排除原基于代价地图的边沿自主探索建图模块 (`explore.launch`, `explore_costmap.launch`, `explore_lite.launch`)。

### 仿真、物理引擎与数据库工具
- **Gazebo 仿真**：排除原 `x3plus_moveit_config` 中与 Gazebo 物理仿真相关的启动入口 (`gazebo.launch`, `demo_gazebo.launch`)。
- **Warehouse 数据库**：排除 ROS 1 依赖 MongoDB 的 MoveIt Warehouse 场景与状态存储服务 (`warehouse.launch`, `warehouse_settings.launch.xml`, `default_warehouse_db.launch`)。
- **MoveIt 外部规划器与基准测试**：排除工业运动规划器 Pilz (`pilz_industrial_motion_planner_planning_pipeline.launch.xml`)、CHOMP 原始 launch 封装以及 OMPL 基准性能测试入口 (`run_benchmark_ompl.launch`)；默认采用 MoveIt 2 OMPL 原生管线与参数化配置。
- **旧 MoveIt 摇杆演示**：不保留 `joystick_control.launch` 及其旧 `moveit_joy.py` 控制链；底盘手柄控制是另一个功能包，不因此被排除。

### 传感器标定与旧式 PID 调参
- 排除原系统基于 ROS 1 动态调参界面的底盘 PID 在线调节工具 (`PIDparam.cfg`)。
- 排除原工程基于旧式 `imu_calib` 节点的 IMU 标定与校准专用启动文件 (`calibrate_imu.launch`, `bringup_calib.launch`) 及简易测试 launch (`test_imu.launch`)。

### 复杂多传感器硬件组合与上位机/APP 互联
- 排除原 ROS 1 中针对 Astra Pro 深度相机点云转激光与底盘复合组合的启动脚本 (`astrapro_bringup.launch`, `laser_astrapro_bringup.launch`, `laser_astrapro_bringup_multi.launch`)。
- 排除原单线激光雷达与 USB 相机、RPLidar 专用带底盘复合启动 launch (`laser_bringup.launch`, `laser_usb_bringup.launch`, `laser_usb_bringup_multi.launch`, `base.launch`, `base_rplidar.launch`)，改由模块化的独立雷达与相机入口解耦加载。
- 排除依赖 ROS 1 `rosbridge_websocket` 与 `world_canvas_server` 的移动端 APP 互联调试启动文件 (`app.launch`)。

### 非 X3plus 底盘特定配置
- 排除原仓库中针对其他非 X3plus 车型变体的历史驱动实现与适配参数 (`Mcnamu_driver.py`)，当前工作空间面向 X3plus 麦克纳姆轮底盘，使用原生 ROS 2 Python 底盘节点与独立 SDK 传输层。

### 独立 AR 与模型依赖验证
- 排除缺少预存标定文件 `B.npz` 的独立摄像头实验 `AR/test.py`；不将该实验记为已经运行或完成迁移的节点。
