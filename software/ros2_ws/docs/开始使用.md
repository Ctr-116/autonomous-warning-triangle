# X3plus ROS 2 Humble 快速上手指南

本指南适用于在 Ubuntu 22.04 LTS 原生环境及 ROS 2 Humble 下快速构建、验证与体验 ROSMASTER X3plus 迁移工作空间。

---

## 1. 前置准备与环境要求

1. **操作系统**：必须为 Ubuntu 22.04 LTS (Jammy Jellyfish)。
2. **ROS 2 版本**：先独立安装官方 ROS 2 Humble（要求 `/opt/ros/humble/setup.bash` 存在）。
3. **原生 Linux 目录**：建议将源码解压到原生 Linux 文件系统（例如 `~/x3plus_ros2_ws`）。WSL2 的 `/mnt/c/` 等 Windows 挂载路径也能读取源码，但构建和 Python 模块导入可能明显变慢。
4. **运行模式说明**：当前所有验证与示例均在本地模拟（Mock）或 Linux 虚拟终端（PTY）模式下运行，未连接真实 Jetson 硬件、物理串口或实车。

---

## 2. 依赖检查、安装与工作空间构建

进入工作空间根目录，依次执行依赖校验、安装与编译：

```bash
# 检查缺失的基础 APT 依赖（不执行安装）
bash scripts/install_dependencies.sh --check-only

# 自动安装缺失的系统与 ROS 2 依赖（调用 apt-get）
bash scripts/install_dependencies.sh

# 编译所有包
bash scripts/build.sh
```

构建说明：
- 默认采用 2 个并行构建线程，以控制内存占用。可通过环境变量调整并发数：
  ```bash
  export X3PLUS_BUILD_WORKERS=2
  export CMAKE_BUILD_PARALLEL_LEVEL=2
  ```
- 可选视觉依赖放在私有环境中，避免覆盖系统 OpenCV 或引入与 Humble 绑定不兼容的 NumPy 2。已验证的私有依赖清单见 `可选视觉依赖.md`。

---

## 3. 加载环境变量

工作空间内置的 Rosmaster 底盘私有 SDK 位于 `vendor/py_install`。每次打开新的终端窗口，均需在工作空间根目录下执行以下命令加载 ROS 与私有 SDK 路径：

```bash
source scripts/environment.sh
```

> **注意**：私有 SDK 会通过 `scripts/environment.sh` 自动附加至当前 Shell 的 `PYTHONPATH`，切勿全局 pip 安装底盘 SDK。

---

## 4. 基础单元测试与集成测试

运行工程测试入口（默认限制为本机 ROS 通信；脚本本身不创建 Linux 网络命名空间）：

```bash
# 执行全部单元测试与基础集成测试
bash scripts/test.sh

# 或者仅执行单元测试
bash scripts/test.sh --unit-only

# 或者仅执行基础模拟集成测试（基于 PTY/Mock）
bash scripts/test.sh --integration-only
```

## 5. 离线联调与组件验证

离线测试套件通过独立脚本启动各子系统验证：

```bash
python3 tests/run_offline.py --suite bringup
python3 tests/run_offline.py --suite model
python3 tests/run_offline.py --suite voice
python3 tests/run_offline.py --suite moveit
python3 tests/run_offline.py --suite nav2
python3 tests/run_offline.py --suite perception
# 独立检查实际 slam_toolbox 初始建图：
python3 tests/run_offline.py --suite slam
```

导航与机械臂验证特性：
- **Nav2**：实际运行必须依赖真实地图文件（YAML/PGM）、TF 树与激光雷达/里程计输入；而离线测试 `python3 tests/run_offline.py --suite nav2` 会自动生成专用的合成地图与仿真数据夹具完成闭环测试。
- **MoveIt 演示**：当前基于 `ros2_control` 模拟硬件进行轨迹规划与夹爪动作执行，严格属于虚拟仿真验证，不代表实体机械臂控制接口已完成实车验收。

离线全量套件说明：
- 运行命令 `python3 tests/run_offline.py --suite core` 按顺序运行上述 6 组核心套件，共 20 个检查程序。2026-11-16 的完整执行已通过，详见 `验证结果.md`。

## 6. 运行模拟节点

在加载了环境的终端中启动模拟底盘与传感器节点：

### 启动基础 Bringup（模拟模式）
```bash
ros2 launch yahboomcar_bringup bringup.launch.py use_mock:=true
```

### 启动语音控制模拟节点
语音控制支持 9 种模式：
- `base`
- `arm`
- `study`
- `line`
- `color_tracker`
- `color_identify`
- `transport`
- `takethings`
- `waypoints`

启动示例（以 `base` 模式为例）：
```bash
ros2 launch yahboomcar_voice_ctrl voice.launch.py \
  mode:=base start_base:=true use_mock:=true enable_serial:=false
```

如需查看各 Launch 文件的所有可用参数，使用 `--show-args`：
```bash
ros2 launch yahboomcar_bringup bringup.launch.py --show-args
ros2 launch yahboomcar_voice_ctrl voice.launch.py --show-args
ros2 launch yahboomcar_nav yahboomcar_navigation.launch.py --show-args
```

## 7. 可选视觉 SDK 与外部依赖

YOLO、MediaPipe 与 dlib 等依赖项不属于基础 APT 包，涉及专用二进制库与模型文件。切勿直接在全局 Python 环境中执行命令安装，请查阅独立的 SDK 部署文档并在独立的 Python 虚拟环境中配置：
- **YOLO ONNX CPU 路径**：使用独立虚拟环境配合 `src/garbage_identify_yolov11/requirements-onnx.txt`。
- **MediaPipe**：使用旧版解决方案 API（如 0.10.9 及 `numpy<2`），避免覆盖系统 OpenCV。
- **dlib**：依赖官方源码在专用环境构建。

---

## 8. 现状说明与注意事项

1. **硬件实机验收**：目前所有验证均为无板卡（No Jetson）、无物理串口的模拟/PTY 验证。若需在实车上启用真实硬件驱动，必须遵循文档与后续实车验收规范，不可凭空声称硬件已完全就绪。
2. **移动端控制网络**：未对任何单一 APK 转换后的控制网络与实际通信进行联调整合测试。
3. **Docker 镜像**：虽然 `Dockerfile` 源码已同步更新完整依赖项，但 Docker daemon 镜像构建尚未经过验证。
