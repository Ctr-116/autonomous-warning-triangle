# 本地构建与模拟验证结果

验证日期：2026-11-10。结论：两个 ROS 2 包构建成功，受测的软件、ROS 节点通信和串口模拟检查全部通过。没有连接物理小车，未进行 Jetson ARM64 构建或实车运行。

## 实际运行环境

- Ubuntu 22.04.5 LTS，x86_64，Python 3.10.12。
- ROS 2 Humble，rclpy 3.3.22，rmw_fastrtps_cpp 6.2.10，Fast DDS 2.6.12。
- colcon-core 0.21.3，pyserial 3.5；使用交付中原始 SDK 3.3.9。
- 运行库来自官方 `ros:humble-ros-base-jammy` 镜像，逐层核对 SHA256 后在 WSL 中的独立 Ubuntu 22.04 根文件系统运行。使用 chroot，未执行交付 Dockerfile 的 Docker daemon 构建。
- 集成测试使用独立 Linux 网络命名空间，只启用其中的 loopback，ROS_LOCALHOST_ONLY=1，ROS_DOMAIN_ID=198，默认 rmw_fastrtps_cpp。未修改 Windows 或 WSL 的持久网络配置。

首次使用宿主 WSL 网络时，最小发布/订阅程序也出现 DDS 发现和消息投递失败；切换到上述独立网络命名空间后，最小程序和全部集成测试通过。此结论只定位到本机验证网络条件，未进一步断言防火墙、代理或 WSL 的具体根因。真实 Jetson 上仍应检查其实际 ROS 网络。

## 构建与入口

`colcon_build.log` 记录 `motion_control_pkg` 和 `x3plus_base` 两个包成功构建。

另在 Linux 文件系统中的全新工作副本执行说明中的 `bash scripts/build.sh` 和 `source scripts/environment.sh`：两个包构建成功，SDK 和两个包可导入，base_node、motion_test_node、test_cli 三个入口均已注册。未构建时加载环境会明确返回失败。交付 shell 脚本语法检查通过，见 `validation/user_scripts.log`。

构建限定 `src`；vendor/COLCON_IGNORE 避免 SDK 的 setup.py 被 colcon 当成第三个独立包。SDK 通过环境脚本加入当前 shell 的 PYTHONPATH。

来源核对已通过：三个输入压缩包与 SOURCE_MANIFEST.json 中的 SHA256 一致，vendor 中四个 SDK 源文件逐一与原压缩包内容相同，见 `validation/source_integrity.json`。

## 单元测试

共 37 项通过：

- 底盘控制与里程计 6 项：速度限幅、指令超时、故障锁定、横向与旋转积分、首帧时间基准、重复及过期反馈处理。
- 运动控制 17 项：指令解析、左右旋转和跨 ±π 的完整转圈、投影距离、里程计新鲜度、无进展与总时限、停止及复位。
- 串口传输 14 项：半包/粘包、长度与校验错误、SDK 实际编码、IMU 换算、非阻塞最新命令槽、写失败和断开、有限退出。

分别见 `validation/base_unit.log`、`motion_unit.log`、`transport_unit.log`。传输故障注入时 SDK 会打印 `set_car_motion error`，对应检查验证该错误没有被原 SDK 的异常捕获掩盖，不代表测试失败。

## 串口与 ROS 集成

- `hardware_transport_smoke.log`：7 项通过。使用真实 SDK、pyserial 与 Linux PTY 模拟控制板，包括启动零速、临时反馈、不操作机械臂/flash、真实字节收发、发送端停顿 watchdog、坏帧、反馈中断、退出和伪终端断开。
- `ros_integration.json`：7 项通过。真实 Humble 图中执行前进 0.2 m、后退 0.2 m、左转 90°、右转 90°，反馈冻结导致故障锁定，软件停止与复位，以及文档中的 `ros2 run motion_control_pkg test_cli` 入口。
- `ros_driver_checks.json`：5 项通过。通过 ROS API 验证速度限幅、指令停止后归零、NaN 指令锁定、多个速度发布者锁定，以及重映射造成命令/反馈同名时拒绝启动。
- `ros_hardware_checks.json`：7 项通过，且退出零速已观测。这里启用 use_mock=false，但连接的是 PTY 控制板模拟器；验证串口后端经 ROS 输出前进、横移、转向里程计和 IMU，指令超时停车，反馈沉默后零速与停止重发旧里程计，反馈恢复后必须显式复位并接收新命令。

最终运动模拟观测约为前进 0.1804 m、后退 0.1804 m、左转 87.13°、右转 -87.19°。控制器在配置的 0.02 m / 3° 容差内结束；这些是理想反馈模拟结果，不能用来声明实车定位或运动精度。精确值保存在 JSON 中。

`validation/exit_status.txt` 中七组检查退出码均为 0。补验 CLI 后的最终集成结果保存在 ros_integration.log/json，ros_launch.log 同时记录两个节点正常退出。

## 复现与验证边界

在 Ubuntu 22.04 / Humble 中按根目录 README 构建，再运行 `bash scripts/test.sh`。脚本使用模拟或 PTY，不打开物理底盘串口。

本次通过证明受测的软件链路可运行；实际固件协议、波特率、电机方向、传感器坐标、轮地误差、断线后的控制板制动行为、Jetson ARM64 依赖和 APP 兼容性仍需实机确认。后续步骤见 `实车验收.md`。LoRa、定位导航、道路感知、机械臂和 150 m 完整部署回收尚未实现于本阶段。
