# 可选视觉依赖与验证指南

本文档面向 Ubuntu 22.04 LTS 与 ROS 2 Humble 环境，说明 X3plus 迁移工程中三个可选视觉套件（MediaPipe、dlib 人脸关键点、YOLO ONNX）的私有环境安装、模型资源准备与离线验证方法。

所有步骤均基于已通过实测的客观事实。ROS 2 的 `cv_bridge` 依赖系统 Ubuntu Python 绑定的 OpenCV ABI，因此可选 Python 依赖必须安装在继承系统包的私有虚拟环境中，严禁直接通过全局 `sudo pip` 覆盖系统 Python、系统 NumPy 或系统 OpenCV。

---

## 1. 架构原则与环境约束

1. **隔离安装**：使用私有虚拟环境（`--system-site-packages`）配合 `pip --no-deps` 安装锁定版本的 wheel，复用 Ubuntu 系统自带的 `python3-opencv`。
2. **硬件架构范围**：本文所列的依赖版本与预编译 wheel 仅在 x86_64（Ubuntu 22.04 / Python 3.10）上完成实测。未声明或保证 Jetson / ARM64 上存在对应二进制 wheel；在 Jetson 设备上部署时必须重新核验编译链与 wheel 可用性。
3. **模型与数据来源真实**：本指南不假设模型已预置，也不虚构一键下载脚本；所列下载地址与 SHA256 均来自真实上游来源记录。工程中原有的 99.7 MB dlib 68 点预测模型（`shape_predictor_68_face_landmarks.dat`）与 Haar 特征 XML 已置于 `yahboomcar_mediapipe/file` 中，构建时会自动安装至 share 目录，无需重复下载。
4. **验证入口环境变量**：离线测试脚本 `tests/run_offline.py` 严格依据环境变量定位私有依赖与测试数据，缺少对应 SDK 或数据时会明确退出并报错，不会伪造测试结果。

## 2. MediaPipe 0.10.9 旧版解决方案（mediapipe 套件）

### 2.1 依赖清单与私有环境创建

MediaPipe 0.10.9 的旧版 API（Solutions API）已在 Ubuntu 22.04 / Python 3.10 x86_64 上完成验证。创建私有环境前需确保系统已安装 `python3-venv`；如需音频相关底层支持，可选系统库 `libportaudio2`。

系统基础包准备：
```bash
sudo apt update
sudo apt install -y python3-venv libportaudio2
```

创建可继承系统包的独立环境并安装锁定清单（共 19 个包，清单文件位于 `src/yahboomcar_mediapipe/requirements-legacy.txt`）：

```bash
python3 -m venv --system-site-packages ~/x3plus_mediapipe_env
~/x3plus_mediapipe_env/bin/pip install --no-deps -r src/yahboomcar_mediapipe/requirements-legacy.txt
```

`requirements-legacy.txt` 锁定的 19 个依赖项如下：

## 3. dlib 19.24.6 人脸特征点 SDK（face 套件）

### 3.1 官方源码来源与校验

人脸关键点检测依赖可选 SDK `dlib==19.24.6`（见 `src/yahboomcar_mediapipe/requirements-dlib.txt`）。实测通过官方 PyPI 源码包在本地进行双线程（2 workers）CMake 构建。不使用未经验证的 pip 并行参数，保证构建环境纯净与 ROS 环境保留。

- 官方源码包：`dlib-19.24.6.tar.gz`
- 官方 URL：`https://files.pythonhosted.org/packages/3c/07/a2693a94ac678c442c4cfe269d24f63053b14410ef2d09957a762eeb4b8e/dlib-19.24.6.tar.gz`
- 大小：3,374,495 字节
- SHA256：`77e3c28ac2c66141514b07cbb74b7c7f80381c019ce5fec99007980bc6490d7d`

### 3.2 独立 CMake 编译至用户私有目录

编译过程必须配置 `CMAKE_LIBRARY_OUTPUT_DIRECTORY` 指向私有目标目录，并确保生成完整的 Python 模块结构（包含 `dlib/__init__.py` 及对应 `.so` 文件）。

实测的 2-worker 编译与安装步骤如下：

```bash
mkdir -p /tmp/dlib_build_workspace
cd /tmp/dlib_build_workspace

# 下载上文固定版本的官方源码包
curl -fL "https://files.pythonhosted.org/packages/3c/07/a2693a94ac678c442c4cfe269d24f63053b14410ef2d09957a762eeb4b8e/dlib-19.24.6.tar.gz" -o dlib-19.24.6.tar.gz

# 校验源码完整性并解压
echo "77e3c28ac2c66141514b07cbb74b7c7f80381c019ce5fec99007980bc6490d7d  dlib-19.24.6.tar.gz" | sha256sum --check
tar -xzf dlib-19.24.6.tar.gz

# 设定私有安装目录（例如 ~/x3plus_dlib_site）
export DLIB_INSTALL_DIR="$HOME/x3plus_dlib_site"
mkdir -p "$DLIB_INSTALL_DIR"

# CMake 配置与双线程构建
cmake -S dlib-19.24.6/tools/python -B build_dlib \
  -DCMAKE_BUILD_TYPE=Release \
  -DPYTHON_EXECUTABLE=/usr/bin/python3 \
  -DCMAKE_LIBRARY_OUTPUT_DIRECTORY="$DLIB_INSTALL_DIR" \
  -DDLIB_USE_CUDA=OFF \
  -DDLIB_NO_GUI_SUPPORT=ON \
  -DDLIB_USE_BLAS=OFF \
  -DDLIB_USE_LAPACK=OFF

cmake --build build_dlib --parallel 2
```

构建完成后，检查 `$DLIB_INSTALL_DIR` 下是否包含生成的模块，并验证版本：
```bash
PYTHONPATH="$DLIB_INSTALL_DIR:$PYTHONPATH" python3 -c 'import dlib; assert dlib.__version__ == "19.24.6"'
```

## 4. YOLO ONNX 推理后端（yolo 套件）

### 4.1 独立环境与依赖清单

YOLO 垃圾识别与检测在 CPU 后端仅使用 ONNX Runtime，不依赖 PyTorch 或 Ultralytics 框架。依赖清单位于 `src/garbage_identify_yolov11/requirements-onnx.txt`。

创建独立虚拟环境并安装：
```bash
python3 -m venv --system-site-packages ~/x3plus_onnx_env
~/x3plus_onnx_env/bin/pip install --no-deps -r src/garbage_identify_yolov11/requirements-onnx.txt
```

清单包含的完整依赖项：

### 4.2 YOLO 套件离线验证执行

## 5. 验证环境变量速查表

| 环境变量名称 | 所属套件 | 类型要求 | 说明 |
| :--- | :--- | :--- | :--- |
| `X3PLUS_MEDIAPIPE_SITE` | mediapipe | 绝对目录路径 | 指向包含 `mediapipe` 0.10.9 的私有 `site-packages` 目录 |
| `X3PLUS_MEDIAPIPE_TESTDATA` | mediapipe | 绝对目录路径 | 包含 `hands.jpg` 和 `pose.jpg` 的测试图片目录 |
| `X3PLUS_DLIB_SITE` | face | 绝对目录路径 | 指向包含已编译 `dlib` 模块的私有输出目录 |
| `X3PLUS_FACE_IMAGE` | face | 绝对文件路径 | 测试使用的人脸测试图片（如 `2007_007763.jpg`） |
| `X3PLUS_FACE_IMAGE_SCALE` | face | 浮点数/字符串 | 人脸图片缩放倍率（小脸样本实测推荐设置为 `"2"`） |
| `X3PLUS_ONNX_SITE` | yolo | 绝对目录路径 | 指向安装了 `onnxruntime` 的私有 `site-packages` 目录 |

各套件验证均由 `tests/run_offline.py` 单独调度。测试套件在环境变量缺失或路径无效时将立即以非零状态码退出并打印对应错误日志，确保验证链路真实有效。
