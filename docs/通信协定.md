## 文档说明

本协定定义本项目各子系统之间的**通信接口、数据格式与异常处理规则**。

**三条使用原则：**

1. 任何跨组的数据交互，都必须以本协定为准，不得自行约定
2. 任何接口变更，须先更新本文档并通知全体，再改代码
3. 文档中 🔲 标记项为待确认内容，由对应组填写后提交 PR 更新

## 一、系统分层与职责边界

| 层 | 负责组 | 核心职责 | 输出什么 |
|---|---|---|---|
| **通信层** | 通信组 | 车内 ↔ 车外的数据通道 | 任务指令、遥测数据 |
| **决策层** | 算法组 | 任务决策与路径规划 | 目标点、速度指令 |
| **感知层** | 传感组 / 视觉组 | 环境信息采集 | 障碍信息 |
| **定位层** | 定位组 | 自身位置估计 | 位置、姿态 |
| **执行层** | 控制组 | 底盘运动执行 | 车轮运动 |

**边界原则：**

- 通信组**只负责数据传输**，不负责数据含义与业务逻辑
- 各组**内部实现自主**，只需遵守对外接口
- 跨组接口的**定义权归属**见第三章

| GNSS 模块 | 🔲 `/dev/gnss` | 定位 | 定位组 |
| 激光雷达 | 🔲 待确认是否串口 | 感知 | 传感组 |
| 其他 | 🔲 待补充 | | |

🔲 **待传感组提供**：所有串口设备的完整清单（设备类型、接口形式、VID/PID）。

**权限处理**：统一使用 `dialout` 用户组，**禁止使用 `chmod 777`**。

## 四、LoRa 无线通信协议

### 4.1 物理层参数

| 参数 | 取值 | 说明 |
|---|---|---|
| 频段 | **433 MHz 或 470 MHz** | ⚠️ 禁止使用 868/915 MHz（非中国频段） |
| 调制 | LoRa（CSS 扩频） | 由模块实现 |
| 扩频因子 SF | 🔲 建议 SF10~SF12 | 优先保证抗干扰 |
| 带宽 BW | 🔲 建议 125 kHz | |
| 串口波特率 | 🔲 待定 | 两端必须一致 |
| 发射功率 | 最大 | |
| **两端配置一致性** | 信道、空中速率、模块地址**必须两端配置完全一致** | 透传模块必需，否则无法通信 |

### 4.2 帧结构

```
┌────────┬──────┬──────┬────────┬────────┬───────┬──────┐
│ 帧头   │ 序号 │ 长度 │ 命令字 │  数据  │ CRC16 │ 帧尾 │
│ 2 字节 │1 字节│1 字节│ 1 字节 │ N 字节 │ 2 字节│1 字节│
│ 0xAA55 │      │      │        │        │       │ 0x5A │
└────────┴──────┴──────┴────────┴────────┴───────┴──────┘
```

| 字段 | 作用 | 说明 |
|---|---|---|
| 帧头 | 定位一帧的起点 | 固定 `0xAA 0x55` |
| 序号 | 判断新旧、去重 | 0~255 循环 |
| 长度 | 确定一帧终点 | **命令字（1 字节）+ 数据段（N 字节）的总字节数**，接收端据此确定还需读多少字节 |
| 命令字 | 说明指令类型 | 见 4.3 |
| 数据 | 具体参数 | 长度可变 |
| CRC16 | 校验数据是否被干扰损坏 | **采用 CRC-16-Modbus**（多项式 0x8005，初值 0xFFFF，低字节在前）；校验范围 = 序号 + 长度 + 命令字 + 数据段（不含帧头帧尾） |
| 帧尾 | 结束标志 | 固定 `0x5A` |

> **帧边界判断注意**：数据段中**可能出现与帧头相同的字节序列**（如 `0xAA 0x55` 恰好是某个参数的取值）。接收端**不应仅依赖帧头匹配**定位一帧，而应结合「长度字段 + CRC 校验」综合判断：匹配到帧头后，按长度读取后续字节并校验 CRC，**只有 CRC 通过才确认是有效帧**，否则视为误匹配，继续向后搜索。

### 4.3 命令字表

| 命令字 | 名称 | 方向 | 数据段内容 | 说明 |
|---|---|---|---|---|
| `0x01` | 前进 | 下行 | 距离（4 字节，单位 mm） | **相对位移**，由算法组基于当前位姿换算为目标点坐标（见 3.5 待确认项） |
| `0x02` | **急停** | 下行 | 无 | **最高优先级** |
| `0x03` | 返航 / 召回 | 下行 | 无 | |
| `0x04` | 模式切换 | 下行 | 模式编号（1 字节） | 🔲 模式定义待算法组确认 |
| `0x10` | 心跳 | 上行 | 无 | **车端定时发送**（1 Hz），供监控端判断车端是否在线 |
| `0x11` | 存活帧 | 下行 | 无 | **监控端定期发送**（≤ 3 秒一次），供车端失联判定；无任务时可复用为心跳 |
| `0x20` | 状态上报 | 上行 | 见 4.4 | 2~5 Hz |
| `0x21` | 异常告警 | 上行 | 异常码（1 字节）+ 说明 | 事件触发 |
| `0x30` | 指令应答 ACK | 双向 | 原指令序号（1 字节） | |

🔲 **待算法组补充**：模式编号定义、异常码表。

### 4.4 状态上报数据段（命令字 `0x20`）

> **编码说明**：为压缩带宽，LoRa 链路采用紧凑编码（下表中的单位），**接收端解码后应换算回 SI 单位**（m、m/s、rad/s）再使用。这并不违反第二章的 SI 约定——约定的是"对外数据一律用 SI"，本节只是"空中传输的编码方式"。

| 字段 | 字节数 | 单位 | 来源 |
|---|---|---|---|
| 电量 | 1 | % | 控制组 |
| 线速度 | 2 | mm/s | 控制组 |
| 角速度 | 2 | 0.001 rad/s | 控制组 |
| 累计里程 | 4 | mm | 控制组（上电清零） |
| 任务状态 | 1 | 枚举 | 算法组 🔲 |
| 经纬度 | 8 | 1e-7 度 | 定位组 🔲 |
| 定位状态 | 1 | 枚举 | 定位组 🔲 |
| 备注 | 1 | 标志位 | 异常告警等 |

🔲 **完整字段清单待各组确认后定稿**，总长度控制在 32 字节以内。

### 4.5 行为规则

| 规则 | 内容 |
|---|---|
| **超时重传** | 发送后 200 ms 未收到 ACK，重发，最多 3 次 |
| **去重（须处理回绕）** | 序号 0~255 循环递增，**禁止用简单大小比较**（否则序号回绕后旧指令会被误判为新指令）。采用有符号差值判断：令 `diff = (收到序号 − 已处理最大序号) mod 256`；若 `diff ≤ 0` 或 `diff > 128`，视为重复或过期，丢弃；否则接受并更新最大序号 |
| **校验失败** | CRC 校验不通过，丢弃整帧，不作任何响应 |
| **心跳方向** | **单向**：车端每 1 秒发送心跳（`0x10`），供监控端判断车端在线；监控端**不需要单独发心跳**——它发送的任何存活帧（`0x11`）或指令都可证明其在线 |
| **失联判定** | 连续 3 秒未收到对方**任何有效帧**（心跳 / 存活帧 / 指令 / 应答），判定链路中断 |
| **半双工与时分** | LoRa 同一时刻只能收或发，因此**禁止双方同时发心跳**。优先级：**下行指令 > 上行遥测**——监控端需要发指令时，车端遥测与心跳暂停让出通道 |

## 五、异常处理与安全机制

### 5.1 异常清单与责任组

| 异常类型 | 发现方 | 上报路径 | 处理方 |
|---|---|---|---|
| 急停触发 | 任一来源 | 直接下发 | 控制组 |
| 定位失效 | 定位组 | 状态机 → 通信组 | 算法组 |
| 雷达失效 | 传感组 | 状态机 → 通信组 | 算法组 |
| 视觉失效 | 视觉组 | 状态机 → 通信组 | 算法组 |
| **通信中断** | **通信组** | 本地处理 + 通知算法组 | **通信组 / 算法组** |
| 超时未到达 | 算法组 | 状态机 → 通信组 | 算法组 |
| 人工接管 | 遥控器 | 硬件直连 | 控制组 |

### 5.2 失联保护分级（通信组负责）

**自最后一次收到监控端有效帧起算**，按累计时长分级处理：

| 累计时长 | 动作 | 理由 |
|---|---|---|
| > 2 秒 | 声光告警（蜂鸣器 + RGB 灯条） | 提示操作员链路异常 |
| > 3 秒 | **判定失联，开始减速** | 不使用急刹，避免麦轮失稳 |
| > 5 秒 | **停车，原地待命** | 相对安全 |
| > 30 秒 | 保持原地（**不自主返航**） | 返航路径存在风险 |

🔲 **待算法组确认**：以上分级是否与其状态机的「安全停止」一致。

### 5.3 指令优先级仲裁

当多条控制路径同时下发指令时，优先级如下：

```
人工遥控（最高）
    ↓
急停（任何来源）
    ↓
远程 LoRa 指令
    ↓
自主算法（最低）
```

🔲 **待控制组确认**：该仲裁由谁实现（STM32 固件 or ROS 层）。

**硬性要求**：**任何指令都不得绕过底盘安全限速。**
